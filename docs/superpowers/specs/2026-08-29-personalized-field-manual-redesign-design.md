# Stellara Work 个性化现场手册设计规格

日期：2026-08-29
状态：已批准

## 1. 背景

Stellara Work 的文档将被重新设计为面向首次使用者的产品学习中心。此次工作不是对现有文档进行换肤、改版或内容修订，而是从目标、内容架构、交互模型和视觉语言开始重新设计。

新文档不使用现有文档的文章结构、目录、正文、组件或排版作为设计参考。公开的 `/docs` 入口继续保留，内部体验由新的“个性化现场手册”完整替换。

## 2. 目标

新文档首先帮助首次使用者独立完成环境配置，并通过连续学习路线掌握从首次启动到可靠交付的核心流程。

核心成功标准：

- 用户无需阅读完整参考手册，即可根据自己的操作系统与模型服务生成专属路线。
- 用户可以在约 45 分钟内完成核心主线。
- 用户可以独立完成安装、模型连接、首次任务和基础交付。
- 每个关键阶段都有明确、可执行的验证任务。
- 验证敏感配置时，网页不读取或保存 API Key。
- 用户可以中断学习并在同一浏览器中恢复进度。
- 用户遇到失败时进入针对性的诊断分支，而不是离开路线自行寻找答案。
- 桌面与移动端均提供经过独立设计的完整体验。

## 3. 非目标

- 不建立用户账号、云同步、数据库或文档后端。
- 不在网页中请求、处理或保存模型服务凭证。
- 不让网页直接调用模型服务验证 API Key。
- 不把所有产品能力都放入必经主线。
- 不保留旧文章 ID、旧章节锚点或旧目录结构作为兼容目标。
- 不把桌面双页布局等比例缩小为移动端页面。
- 不通过大量动画、装饰或游戏化机制干扰阅读。

## 4. 产品定位

产品形态为“个性化现场手册”：一本根据用户当前设备和模型服务单独编排的操作指南。

体验原则：

- **成果导向**：章节以用户能够完成的成果命名，而不是按产品模块分类。
- **路线优先**：首页直接展示当前配置路线、进度和下一步，不先展示内容库总览。
- **解释适量**：正文采用冷静的专业导师语气，说明必要原因，但不堆砌术语。
- **验证闭环**：每个关键步骤以验证结束；通过则推进，失败则诊断。
- **主线精简**：核心主线只包含成功使用产品所需内容，其余内容作为可选支线。
- **快速可查**：全局搜索直接返回可执行步骤、诊断路径和术语解释。

## 5. 内容架构

### 5.1 核心主线

核心主线预计约 45 分钟，按成果划分为四卷：

1. **准备好设备，约 8 分钟**
   - 确认操作系统与安装包。
   - 完成安装与首次启动。
   - 处理平台安全提示。
2. **接通智能能力，约 12 分钟**
   - 选择模型服务。
   - 填写适用于该服务的连接信息。
   - 在 Stellara Work 内运行连接测试。
   - 回到文档记录通过或失败结果。
3. **完成第一个成果，约 12 分钟**
   - 准备工作目录。
   - 发起一个边界清楚的真实任务。
   - 理解执行过程和需要用户介入的时刻。
   - 验收首次输出。
4. **建立可靠工作习惯，约 13 分钟**
   - 理解并处理安全审批。
   - 查看任务进度和上下文状态。
   - 核对结果与交付范围。
   - 正确完成任务并继续下一项工作。

### 5.2 可选支线

支线不阻塞核心主线，可从章节、搜索结果或路线目录进入：

- 更换模型服务或连接方式。
- 处理安装、连接和运行错误。
- 提升任务描述与输出质量。
- 深入理解工具、安全、上下文和本地数据。
- 使用高级能力处理更复杂的任务。

### 5.3 单节内容模板

每个学习步骤使用统一结构：

1. 目标。
2. 预计时间与准备条件。
3. 操作步骤。
4. 验证任务。
5. 常见问题或失败入口。
6. 完成状态与下一步。

正文只包含完成当前结果所需的信息。背景知识放入页边注、术语解释或可选支线，避免打断主流程。

## 6. 个性化路线

### 6.1 用户输入

首次进入时收集最少必要信息：

- 操作系统及架构。
- 使用的模型服务类型。
- 阅读主题偏好可跟随系统，不作为路线条件。

系统可以提供合理的默认检测结果，但用户必须能够确认和修改。

### 6.2 路线生成

路线生成器从课程目录中筛选符合条件的步骤，并保持成果顺序。条件可基于平台、架构、模型服务和内容版本。

生成结果包含：

- 核心主线步骤。
- 当前步骤。
- 预计剩余时间。
- 适用于当前配置的可选支线。
- 已完成、需复查和被诊断分支暂时阻塞的状态。

用户更换操作系统或模型服务后重新生成路线。仍然适用且内容版本未变化的完成记录继续保留。

## 7. 视觉设计

### 7.1 视觉语言

视觉方向为“编辑手册”：温暖纸张、现代宋体或衬线标题、清晰无衬线正文、章节编号和克制的印刷细节。

它应像一本为当前用户单独编排的现场指南，而不是应用仪表盘、开发者控制台或通用文档模板。

### 7.2 色彩

日间版：

- 主纸张：暖象牙色。
- 次纸张：浅羊皮纸色。
- 正文：深暖褐黑。
- 强调：克制的砖红色。

夜间版：

- 主底色：暖墨黑，不使用纯黑。
- 次底色：深棕灰。
- 正文：暖米白。
- 强调：较明亮的陶土红。

默认跟随系统主题，顶栏允许手动切换日间版与夜间版。

### 7.3 字体

- 章节标题：现代宋体或具有中文阅读质量的衬线字体。
- 正文与控件：中性、高可读性的无衬线字体。
- 命令、路径和字段值：等宽字体。
- 字体应自托管或使用可靠的本地回退，不依赖运行时第三方字体请求。

### 7.4 动效

动效只用于解释状态变化：页面淡入、目录切换、验证结果和诊断分支展开。不得使用持续循环装饰动画。

系统启用减弱动效时，所有过渡立即完成，内容顺序、焦点和状态播报保持不变。

## 8. 页面与组件

### 8.1 顶栏

顶栏包含：

- Stellara Field Notes 品牌标识。
- 当前路线与总进度。
- 全局搜索入口与快捷键提示。
- 完整目录入口。
- 日间版与夜间版切换。
- 本地数据与路线设置入口。

### 8.2 桌面端：手册摊页

桌面端使用双页结构：

- 左页展示路线名称、个性化条件、总进度、四个成果章节和当前位置。
- 右页展示当前步骤的目标、操作、验证任务和下一步。
- 双页之间使用轻微书脊层次，但不模仿真实翻页动画。
- 阅读区保持稳定宽度，路线切换不造成大幅布局跳动。

### 8.3 移动端：单页模式

移动端重新编排为单页：

- 顶部显示当前章节和总进度。
- 路线目录从抽屉或独立视图打开。
- 正文占据完整阅读宽度。
- 当前验证动作固定在容易触达的位置，但不得遮挡正文或系统浏览器控件。
- 搜索、主题和本地设置保持完整可用。

### 8.4 关键组件边界

- **现场手册外壳**：主题、顶栏、响应式布局和全局导航。
- **路线目录**：成果章节、步骤状态、预计时间和当前位置。
- **章节阅读器**：结构化正文、提示、命令和页边注。
- **验证任务**：应用内操作说明、通过/失败选择和状态记录。
- **诊断分支**：根据错误现象给出连续排查步骤，并支持返回原路线。
- **全局搜索**：检索步骤、诊断、术语和支线内容。
- **本地数据设置**：修改个性化条件、重置路线、清除全部本地数据。

## 9. 验证与诊断

### 9.1 安全边界

模型连接等敏感验证只在 Stellara Work 内执行。网页不得提供 API Key 输入框，也不得接收、缓存或转发密钥。

文档向用户说明如何在应用内运行测试。用户返回文档后选择“验证通过”或“验证失败”。

### 9.2 通过路径

选择通过后：

1. 保存验证结果。
2. 将当前步骤自动标记为完成。
3. 更新路线进度。
4. 显示简短完成反馈。
5. 提供下一步入口。

### 9.3 失败路径

选择失败后不完成当前步骤，而是根据应用显示的现象进入诊断分支，例如：

- 未授权或凭证无效。
- 找不到服务地址。
- 请求超时或网络不可达。
- 协议或路径不匹配。
- 其他错误。

诊断分支中的每一步都必须提供验证方法。修复成功后返回原步骤，保留诊断上下文并重新执行验证。

## 10. 全局搜索

搜索索引在构建阶段生成，查询完全在浏览器本地执行。

搜索范围包括：

- 学习步骤标题和正文。
- 验证任务。
- 诊断分支和错误现象。
- 术语与同义词。
- 可选支线。

结果优先级为：匹配错误现象的诊断步骤、当前路线中的可执行步骤、其他教程、术语解释。

结果按类型分组，并显示所属路线、预计时间和内容类型。键盘可以完成打开、选择和关闭操作。搜索脚本不可用时，退化为可浏览的完整内容索引。

## 11. 内容与状态模型

### 11.1 内容模型

课程内容使用新的结构化模型，不延续旧文章数组。概念边界如下：

```ts
type LearningStep = {
  id: string;
  contentVersion: number;
  outcome: string;
  estimatedMinutes: number;
  conditions: RouteCondition[];
  sections: LessonSection[];
  validation?: ValidationTask;
  diagnosticBranches?: DiagnosticBranch[];
  relatedTracks?: string[];
};
```

所有路线、步骤和诊断节点使用稳定 ID。内容构建时必须校验引用完整性。

### 11.2 本地状态

浏览器只保存：

- 状态 schema 版本。
- 用户确认的平台与模型服务类型。
- 生成的路线 ID。
- 已完成步骤及对应内容版本。
- 用户选择的验证结果。
- 已确认阅读的内容更新。
- 主题偏好。

不得保存 API Key、模型服务凭证、应用配置或完整错误日志。

## 12. 数据流

### 12.1 首次访问

1. 读取本地状态。
2. 无状态时进入最短个性化问答。
3. 用户确认平台与模型服务。
4. 路线生成器生成核心路线与支线。
5. 本地保存配置和路线 ID。
6. 打开路线首页与第一个未完成步骤。

### 12.2 日常学习

1. 页面根据路线与进度渲染目录。
2. 用户完成内容并执行验证。
3. 通过结果写入本地状态并推进路线。
4. 失败结果打开诊断分支，不改变完成状态。
5. 用户下次访问时恢复当前位置。

### 12.3 内容升级

1. 比较本地步骤版本与当前内容版本。
2. 未变化步骤保留完成状态。
3. 发生变化的已完成步骤标记为“有更新，请复查”。
4. 用户阅读并确认后更新本地记录。
5. 已删除或不再适用的步骤从新路线中移除，不保留悬空状态。

## 13. 异常处理

- **本地存储不可用**：进入临时会话模式，明确提示关闭页面后进度会丢失。
- **本地状态损坏**：停止读取损坏状态，解释问题，并在用户确认后重置；不得静默清除。
- **路线条件变化**：重新生成路线，保留仍适用且版本一致的完成记录。
- **验证失败**：进入对应诊断分支，主线保持当前位置。
- **未知错误类型**：提供通用诊断路径、错误搜索和返回原步骤操作。
- **搜索索引不可用**：展示完整可浏览索引。
- **步骤或链接不存在**：返回路线首页并解释内容已移动，不显示空白页。

本地数据设置必须将“重置当前路线”和“清除全部本地数据”分开，并分别二次确认。

## 14. 无障碍要求

- 满足 WCAG 2.2 AA 对比度要求。
- 所有功能可通过键盘完成。
- 使用正确的标题层级、页面地标、标签和焦点顺序。
- 搜索打开、页面切换、验证结果和诊断分支必须管理焦点。
- 状态变化使用辅助技术可读取的即时播报。
- 完成、失败、锁定和更新状态不得只依赖颜色。
- 支持系统减弱动效偏好。
- 触控目标、正文行长、字号和行距在移动端保持可读可操作。

## 15. 测试策略

### 15.1 内容与路线测试

- 校验所有路线、步骤和诊断 ID 唯一。
- 校验所有引用存在，无死链接或悬空诊断节点。
- 遍历支持的平台与模型服务组合，确认每条路线可生成并抵达完成状态。
- 校验每个失败分支都能返回原步骤或明确结束。
- 校验总时长和步骤顺序符合核心主线设计。

### 15.2 状态测试

- 保存与恢复路线进度。
- 更换平台或模型服务后的路线重建。
- 内容版本升级与“请复查”状态。
- 损坏数据恢复。
- 本地存储不可用时的临时模式。
- 重置路线与清除全部数据的隔离。

### 15.3 交互测试

- 首次生成专属路线。
- 验证通过后自动推进。
- 验证失败后进入诊断并返回。
- 搜索结果排序、键盘导航与索引降级。
- 日间版、夜间版和系统主题变化。
- 桌面双页与移动单页导航。

### 15.4 无障碍与视觉测试

- 自动无障碍扫描与人工键盘检查。
- 屏幕阅读器检查关键状态和焦点恢复。
- 减弱动效模式检查。
- 日间与夜间主题对比度检查。
- 桌面、平板、手机的视觉回归截图。

### 15.5 端到端场景

端到端测试至少覆盖：

1. 首次访问并生成路线。
2. 完成安装和配置步骤。
3. 验证失败，进入诊断，修复后通过。
4. 中断并恢复学习进度。
5. 完成核心主线。
6. 内容版本升级后复查变化步骤。

## 16. 已确认决策

- 产品形态：产品学习中心。
- 核心受众：首次使用者。
- 首要成果：独立配置环境。
- 内容组织：引导式学习路径。
- 首页：配置路线首页。
- 进度：自动记录。
- 个性化：根据操作系统与模型服务生成专属路线。
- 验证：应用内执行，用户在文档选择通过或失败。
- 失败处理：进入分支诊断。
- 后续学习：连续学习路线。
- 主线范围：核心主线加可选支线。
- 章节逻辑：按成果推进。
- 主线时长：约 45 分钟。
- 文案语气：冷静的专业导师。
- 快速查找：全局搜索。
- 视觉语言：编辑手册。
- 核心布局：桌面手册摊页，移动单页模式。
- 主题：日间纸张加夜间墨色，默认跟随系统。
- 数据：仅保存于当前浏览器。
- 版本更新：保留进度并标记变化步骤复查。
- 技术形态：静态站点，无后端。
